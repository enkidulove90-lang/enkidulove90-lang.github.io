LLM增强的推荐去噪框架

发表于2026-10-19|更新于2026-10-20|未分类
|总字数:1.4k|阅读时长:4分钟|浏览量:

论文：arXiv 2502.09058 · 代码：GitHub

隐式反馈里的噪声，靠什么判

推荐系统大量依赖隐式反馈：点击、播放、加购。这些信号便宜、量大，但天然带噪——误点、随手加购、为别人买的礼物，全都被当成”喜欢”喂进模型。噪声一旦进入训练，用户偏好画像就被带偏。

已有的去噪思路大致两类：一类引入辅助信息（额外特征、跨域信号），另一类从交互数据本身学去噪策略。问题是两条路都有天花板：辅助信息受限于外部知识的可得性和质量；从交互里学则依赖某些预设假设（比如”噪声样本的 loss 更大”这类先验），一旦假设不成立，判噪就不准了。

LLaRD 的思路是引入第三种信息源：让 LLM 来提供去噪知识。论文的动机很直接——LLM 有世界知识和推理能力，但它在”推荐去噪”这件事上的潜力此前没被认真挖过。

机制：三段式知识生成，最后用信息瓶颈收口

LLaRD 生成两类去噪知识，再引入一个约束把它们对齐到推荐目标：

① 偏好知识生成。 先从观测数据里用 LLM 丰富语义洞察，并推断用户-物品的偏好知识。这一层回答的是”用户大概喜欢什么”。

② 关系知识生成。 在用户-物品交互图上做 Chain-of-Thought 推理，揭示实体之间的关系知识。这一层回答的是”哪些交互之间的关系能帮我判断真假”。

③ 知识增强去噪。 前两步生成的知识不可能全是有效的——LLM 会带进无关内容甚至幻觉。所以最后用信息瓶颈（Information Bottleneck）原则，把 LLM 生成的去噪知识与推荐目标对齐，把噪声和无关知识滤掉。

第三层是整条链路能成立的关键：**LLM 给的知识是”候选”，不是”答案”**。少了 IB 这一步，生成式知识带来的噪声会抵消掉它带来的信息。

为什么这套组合能解决前面的天花板

把三层对照着前面两个瓶颈看就清楚了：

  • 不依赖外部辅助信息。 偏好知识和关系知识都是从现有观测数据 + 交互图里推出来的，不需要额外特征工程或跨域数据，绕开了”外部知识不可得”的限制。

  • 不依赖脆弱的预设假设。 传统方法假设噪声在某种统计意义上可区分（loss 大、梯度异常……）。LLaRD 让 LLM 从语义和关系两个角度给出内容层面的判断依据，避免了”假设不成立就集体失效”的风险。

  • IB 把生成式知识纳入了可控范围。 这一步相当于给 LLM 的输出加了一道与任务目标挂钩的过滤器，让它只保留对推荐有用的部分。

实验说明了什么

三个基准数据集、两个主流骨干模型（GMF / LightGCN）：

  • LLaRD 在所有数据集、两个骨干上都稳定领先主流去噪方法；

  • 相对第二好的方法 BOD，平均提升约 6.92%（GMF） 与 11.79%（LightGCN）；

  • 对交互数据驱动的去噪方法（T-CE、DeCA、DCF、SGDL）的提升幅度达到 **46.1%–68.53%**——这类方法受限于只能从观测数据内部找模式、靠训练 loss 判噪，LLaRD 从语义与关系两个外部视角切入，差距就体现在这里；

  • 作为对照，LLM 增强方向的 RLMRec 也明显优于 SGL、SimGCL 这类传统对比学习基线（约 +14.93%），说明”引入 LLM 的任务相关知识”这条路线本身是有效的；

  • 在不同噪声水平的扫描下，以及不同冷启动水平下，LLaRD 都保持领先。

三点可以抄走的

  1. 让 LLM 输出”候选知识”，再用任务目标过滤，而不是直接信它。 把 IB 这类与任务对齐的约束放在生成之后，是生成式知识能落地的前提条件。

  2. 在图上做 CoT，而不是在文本上做。 关系知识的价值来自交互图的结构，沿图做推理比在纯文本提示里做更贴合推荐场景。

  3. 去噪评估要扫噪声水平，而不是只看一个点。 论文的噪声水平扫描与冷启动分层结果才是真正说明”去噪能力”的证据；单点指标很容易被别的因素掩盖。

总结

LLaRD 把去噪问题的信息源从”辅助特征”和”交互统计”扩到了”语义 + 关系知识”，并用信息瓶颈把生成式知识约束回任务目标。三段式结构里，前两段负责”找依据”，第三段负责”别把新噪声引进来”——后者才是这套方法区别于”随便加个 LLM 模块”的地方。

复现时的优先级：先验证 IB 对齐模块的消融（如果去掉它性能不降，说明 LLM 知识的贡献本来就有限），再看关系知识部分相对偏好知识部分的边际收益。
