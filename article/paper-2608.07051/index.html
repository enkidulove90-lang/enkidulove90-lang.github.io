YOLO-PEFT：把适配器放置变成可审计的约束规划，并在 RT-DETR 上学会拒绝

发表于2026-08-07|更新于2026-10-25|推荐系统论文速递
|总字数:3k|阅读时长:10分钟|浏览量:

论文：arXiv 2608.07051 · 代码：GitHub · 代码：GitHub · PDF：本地阅读

把语言模型上的 LoRA 直接搬到实时检测器上，常常不是效果差一点，而是悄无声息地崩掉。现代检测器把稠密卷积、分组卷积、深度可分离卷积、与损失耦合的 DFL 投影、可变形注意力、文本—图像融合和 MoE 路由交织在同一张图里，按模块名或模块类型选目标的做法在这里失去了前提。YOLO-PEFT 的出发点正是这个错位：PEFT 的“可插入性”不是参数化问题，而是宿主图的结构问题。

这篇论文的定位不是再提出一种低秩参数化。作者明确把检测器 PEFT 重述为异构计算图上的多约束规划问题，并给出一个覆盖训练、仅适配器检查点、合并与 ONNX/TensorRT 导出的运行时契约。换句话说，它更像一层“放置决策 + 部署落地”的基础设施，而不是又一个 adapter 变体。

论文真正想解决的核心矛盾是：PEFT 的可靠性强烈依赖架构，而现有接口默认存在一个跨架构通用的排序。作者用 14 种 PEFT 变体在 5 种异构检测器上做诊断扫描，发现灾难率随注意力比例上升，且没有一种排序能在五个家族间保持一致。这直接支撑了“训练前拒绝”这一设计：当没有可靠方案时，返回 Refuse 并回退到全量微调，比训练一个注定失败的适配器更合理。

需要提前说明边界。所有结论都限定在 VOC07+12 trainval→VOC07 test 协议和已评估的检测器家族内；Refuse 规则是在已观测的 RT-DETR-L 崩溃上校准的，不是对未见架构的安全保证。核心 s-scale 运行使用 600 epoch 上限与 640×640 输入，诊断扫描使用 300 epoch 与 320×320 输入，两者不混合统计。

一、方法：从角色感知图到可拒绝的放置计划

YOLO-PEFT 把检测器表示为有向无环图 G=(V,E)，每个模块 i 由四元组 z_i=(o_i,s_i,q_i,h_i) 描述：算子元数据（类型、形状、分组、卷积核与初始化）、语义角色（backbone、neck、分类、回归、DFL、decoder、router、expert）、图接口元数据（输入输出元数、张量形状、残差/融合边）以及部署元数据（后端支持、可合并性、导出器支持）。规划请求 R=(p,T,L,K) 包含变体、可选目标集、可选层区间与允许秩集合，在预算 B 下返回放置 π 或 Refuse。

关键设计是双角色解析。同一个 Conv2d 可能属于 backbone 块、特征金字塔融合、回归头或固定的 DFL 投影，仅凭 Python 类型无法判断是否安全。算子角色决定适配器形状是否合法：稠密卷积接受普通低秩因子，分组卷积需要组内因子且要求 G|r，深度可分离卷积不能接受混合通道的更新；语义角色决定检测器层面的安全性：固定 DFL 投影、几何敏感的回归路径和 MoE 路由被排除，因为微小更新就可能改变校准分箱或专家分配。

规划器按固定顺序执行：算子过滤、语义过滤、应用架构策略、预算感知秩分配、可靠性校准。每个约束返回布尔决策与原因码，输出为 (d,π,J)，其中 d∈{ACCEPT,REFUSE}，J 是有序拒绝日志。这个设计把“不支持”和“预测会崩”区分开，避免同一个 Refuse 掩盖不同原因。预算分配求解 max Σu(i,π(i)) s.t. Σc_p(i,π(i))≤B，其中线性层与卷积层的成本按 b·r·(d_in+d_out) 与 b·r·(C_in·k_h·k_w+C_out) 计算，分组卷积按组内求和。

可靠性校准使用 10 维架构指纹中的五个核心维度——注意力、文本融合、MoE 专家、深度可分离卷积、稠密/分组卷积的相对占比——拟合 ΔmAP 的线性模型，当预测低于灾难阈值 −0.05 时触发拒绝。作者强调规则模式是默认，校准模式只在已观测架构上做 LOVO 评估，不外推到未见家族。

运行时契约维护四个不变量：基础检查点加载不变、适配器检查点只存适配器张量与运行时元数据、合并后恢复普通 YOLO 模块、ONNX/TensorRT 导出器看到可导出的图。对于回退的分组卷积 LoRA 后端，每个组内更新 ΔW_g=B_gA_g^T 被重塑到宿主卷积核分区后合并，由于更新在各卷积组内独立构造，移除包装器保持分组结构，输出在浮点容差内等价。

这张矩阵图是全文论证的枢纽。横轴是五种异构检测器家族，纵轴是 14 种 PEFT 变体，单元格颜色表示相对全量微调的 ΔmAP。阅读顺序建议先看红色单元格的分布：在纯卷积的 YOLO11n 上十次运行零崩溃，而在 YOLO12n 上是 6/7，在 RT-DETR-L 上是 7/7。颜色随注意力比例 φ_attn 上升而整体变红，说明失败不是随机噪声，而是与宿主图的注意力密度相关。它支撑的主张很直接：不存在跨架构通用的 PEFT 排序，因此放置必须条件化于架构，且拒绝必须成为一等结果。

二、实验：VOC 协议下的放置收益与系统代价

实验遵循官方 Ultralytics VOC 配置：VOC2007 trainval（5,011 张）与 VOC2012 trainval（11,540 张）合并为 16,551 张训练图像，官方 VOC2007 test 为 4,952 张。核心 s-scale 运行使用 600 epoch 上限与 640×640 输入；14 变体×5 架构诊断扫描使用 300 epoch 与 320×320 输入。优化器为 SGD（初始学习率 0.01，动量 0.9，权重衰减 5e-4），余弦调度，最后 10 个 epoch 关闭 Mosaic。PEFT 默认 r=16、α=32、dropout=0.05、RS-LoRA 缩放。种子为 {0,28,42}，组内最大标准差 ≤0.006 mAP50:95。

主结果如下表（seed-0 核心矩阵，Δ 为相对同 backbone Full-SFT 的 mAP50:95 变化）。

最强的相关基线是 HRA：在 YOLO11s 上达到 0.7276（+0.0848），在 YOLO12s 上达到 0.7453（+0.0791），均高于规划器选择的 RS-LoRA。这说明“规划器选择”并不等于“全局最优变体”，而是在约束下给出可部署的可行解。另一个值得注意的例外是 YOLO12s 上 LoRA+DoRA 且无 RS-LoRA 缩放时 Δ=-0.0550，直接越过灾难阈值，说明训练先验之间存在非加性交互，不能孤立报告。

RT-DETR-L 一行是拒绝机制的直接证据：七种被扫描的 LoRA 族配置全部低于 Δ=-0.05，规划器返回 REFUSE 而非适配器。作者明确这是已评估覆盖范围内的校准规则，不是对未见架构的测试。

系统代价方面，受控 YOLO11 审计显示 LoRA 将峰值显存从 28.57 GB 降至 16.03 GB（43.9%），但训练时间从 118.2 秒增至 203.8 秒（1.72 倍）。合并后的部署收益在 MPS 审计中体现为：YOLO11s 延迟从 27.719 ms 降至 17.933 ms，吞吐量从 36.076 提升至 55.763 img/s；YOLO12s 延迟从 35.095 ms 降至 24.881 ms，吞吐量从 28.494 提升至 40.191 img/s。

消融部分，规划器约束在 YOLO12s 上的逐级贡献为：无约束 0.6900，加入算子有效性过滤后 0.7094，再加入检测头语义排除后 0.7307，完整规划器保持 0.7307。语义排除带来最大的一步稳定性提升，支持“语义守卫是稳定性驱动而非工程保险”的判断。

秩敏感性上，YOLO12s 从 r=8 的 0.7288 提升到 r=16 的 0.7307，再到 r=32 的 0.7363，但参数与推理 GFLOPs 从 9.66M/23.6 增至 10.85M/29.6，作者据此把 r=16 视为实时检测器的实用 Pareto 点。谓词级诊断还显示，打开注意力流规则会多接纳 32 个模块并把平均适配器梯度范数提高 1.581 倍，打开类型化头部规则会多接纳 18 个模块并提高 1.091 倍，但短程运行未出现非有限梯度，因此证据支持的是优化压力改变而非必然崩溃。

三、总结

YOLO-PEFT 的机制可以概括为：用双角色图解析把模块的算子契约与检测语义分开，用有序约束过滤把不安全目标在训练前排除，用预算感知的秩分配在剩余目标上求解，用校准的可靠性模型在覆盖范围内触发 Refuse，最后把接受的计划降低到训练—仅适配器保存—合并—导出的统一运行时。实验证据显示，在 VOC 协议下规划器选择的 RS-LoRA 在 YOLO11s 与 YOLO12s 上分别达到 0.7138 与 0.7307，超过全量微调的 0.6428 与 0.6662；RT-DETR-L 上七种 LoRA 族配置全部越过灾难阈值，规划器返回 Refuse；受控审计测得峰值显存降低 43.9%，但训练时间增加 1.72 倍。

限制同样明确。所有结论限定在 VOC 与已评估的检测器家族，Refuse 规则是在已观测崩溃上校准的，未见架构上的假拒绝/假接受率无法从当前矩阵计算；COCO 与域偏移评估、区域级微调基线、专家感知的 MoE 规划都仍是未来工作。此外，规划器选择的变体并非全局最优，HRA 在两个 backbone 上都更高，说明约束规划解决的是可行性与可部署性，而不是变体搜索的上界。

可迁移的设计启示是：当适配器方法从同构 Transformer 迁移到异构图时，应把“是否允许插入”与“插入后效果如何”分成两个阶段，前者用确定性约束与原因码保证可审计，后者用校准模型在有限覆盖内给出风险估计，并允许系统在证据不足时拒绝而不是猜测。这一决策规则对任何需要在异构模块图上做参数高效适配的部署流水线都适用。
