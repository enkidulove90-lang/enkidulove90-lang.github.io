LLM 表征拼进多模态推荐为什么掉点：RecGOAT 的双粒度对齐

发表于2026-10-19|更新于2026-10-20|未分类
|总字数:2.1k|阅读时长:6分钟|浏览量:

论文：arXiv 2602.00682 · 代码：GitHub

多模态推荐这两年最常见的做法，是把大模型的表征当成”更好的特征”：文本走 Qwen-Embedding、图像走 LLaVA，再把它们和 ID 嵌入拼在一起送进图网络。这套流程看起来顺理成章，但 RecGOAT 这篇论文指出一个被忽略的前提问题——生成式模型的表征和协同过滤的 ID 信号，语义空间根本不在同一个坐标系里。

一个反直觉的观察：加了 LLM 反而更差

论文先在 Baby 数据集上做了一组对照，比较”LM 表征对齐前 / 对齐后”对推荐效果的影响（Figure 1）：

这张图是全文的动机来源。左图（未对齐）里，随着 LM 表征在最终表示中的比重上升，推荐指标不升反降——也就是”模型懂的东西更多了，推荐反而更差”。论文把原因归结为 semantic heterogeneity：LLM 的文本/图像嵌入是围绕”语言语义”组织的，而 ID 嵌入是围绕”共现统计”组织的，两者直接拼接时，模型拿到的是两组互不兼容的坐标系。右图（对齐后）曲线整体上移、单调性也恢复了。

这也解释了为什么不少”LLM 增强推荐”的工作只在个别数据集小幅涨点：不改对齐方式，堆多强的模型都是在往系统里注入噪声。

RecGOAT 的整体设计

针对这个问题，RecGOAT 提出”双粒度对齐”：实例级对齐（跨模态对比学习）+ 分布级对齐（最优自适应传输），并把它嵌进一个多模态图推荐骨架里。

这张框架图自上而下分四段，正好对应论文的四个模块。①LM 增强模态抽取：文本描述交给 Qwen-Embedding、图像交给 LLaVA，另外用一段”用户偏好推理”提示词让 LLM 从交互历史里推断偏好；②结构关系学习：不是只建一张用户-物品交互图，而是并行建 item-item 文本图、item-item 图像图、user-item 交互图、user-user 文本图，用注意力揉合多跳协同信号；③双粒度对齐（全文核心）：左半边是实例级对齐（CMCL 约束），右半边是分布级对齐（OAT 约束）；④融合与推荐：把对齐后的模态表征与 ID 表征加权拼成统一的物品/用户表示，只用一个 BPR 损失收口。

值得注意图里”没有”的东西：没有一堆支路损失。对比损失和传输损失都作用在最终统一表示上，而不是各自独立优化某个子模块——这个设计选择在后面的消融里被证明是关键的。

机制一：实例级对齐（CMCL）

细粒度对齐靠跨模态对比学习。核心是 InfoNCE：同一物品在不同模态下的表示互为正样本，batch 内其他物品的表示充当负样本。

它的作用是拉近同一个物品在不同模态下的表示——解决的是”实例级”的错位。但论文指出，只做到实例级还不够：它管不住两个模态的整体分布形状，也就是”这一整批文本嵌入的方差/协方差结构与图像嵌入是否可比”。

机制二：分布级对齐（OAT）——为什么不是 KL

第二层对齐直接对齐分布，用的是 Wasserstein 距离（最优传输），而不是常见的 KL 散度。论文给的理由很直白：KL 是非对称的、且要求两个分布有重叠支撑，当文本嵌入和 ID 嵌入的支撑集几乎不重叠时，KL 的梯度会退化；Wasserstein 距离则能在”两个分布离得很远”时依然提供有意义的梯度。

工程上这里做了一个很重要的简化：不做节点级的 OT 匹配（那是 O(n²) 的代价，工业规模下不可行），而是只对齐分布，计算量依赖特征维度 d。线上落地时用的是二阶矩闭式，只要均值和协方差：

即”均值距离平方 + 两个协方差矩阵之间的 Bures 距离”。落地实现里，物品侧的模态向量和 ID 向量先各过两层 DNN 做非线性映射，再算这个距离。

为什么”融合更好”是有保证的

论文给了一个理论结果（不是启发式）：统一表示的目标误差 ε_F(f) 小于任一单模态的误差 ε_m(f)，并且误差差距被 Wasserstein 距离与 InfoNCE 损失界住。含义是：对齐做得越好（W 越小、对比损失越低），融合相对单模态的优势就越有保证——这正好把”双粒度”两层的设计动机串了起来。

实验

三个 Amazon 数据集（8:1:1 划分 / 5-core）：

指标为 Recall@10 / NDCG@10，取 10 次运行平均。论文报告的三条结论：

  1. 多模态方法（FindRec、FREEDOM）整体优于纯 ID 方法（LightGCN），说明多模态信息确实在缓解交互稀疏；

  2. RecGOAT 明显超过 LLM 增强类基线（Electronics 上 R@10 为 0.0468 vs 0.0419）；

  3. RecGOAT 优于 IRLLRec（用对比学习 + KL 做对齐），这被论文当作”Wasserstein 优于 KL”的直接证据。

消融实验是这篇最值得看的部分（Baby 数据集）：

这张表的前两行是关键负结果：直接拼接几乎没收益，朴素相加甚至比只用 ID 掉了约 12%（0.0479 → 0.0422）——这就是引言里那个”加了 LLM 反而更差”的量化版本。而单独加任一层对齐都能把指标从 0.047 抬到 0.060 以上，两层叠加再涨一截。

论文还专门检验了”对齐一致性”：把最终表示里两个模态的权重系数（γ_t、γ_v）在 0–0.8 之间扫一遍，性能曲面很平（数值集中在 0.0645–0.0665 这一窄带内），说明对齐之后不同模态的表征已经”可比”，怎么加权都不容易崩。

这张热力图是”对齐一致性”的证据：横轴和纵轴分别是文本模态与视觉模态的权重系数（各 0–0.8），格子里的数字是推荐指标。如果两个模态的表示不可比，权重一变性能就会剧烈波动；实测整片区域的数值只在一个很窄的区间内浮动，说明对齐之后两者的坐标系已经被拉到同一尺度上，融合权重不再是”需要精调的敏感超参”。

线上 A/B：论文把 OAT 组件部署进一个大规模广告系统，对 5% 流量（约 2000 万用户）做测试，广告主价值（ADVV）提升 **1.5%**。工业推荐里这个量级不算小。

总结

RecGOAT 的价值不在”又一个多模态推荐模型”，而在它把”LLM 表征怎么和 ID 信号共存”这件事讲清楚了：语义错位是真实存在且可量化的（Baby 上掉 12%），解决办法分两层——实例级用对比学习对齐细节、分布级用最优传输对齐形状，并且有理论保证融合优于单模态。工业侧只挂 OAT 组件就能拿到 1.5% 的 ADVV 提升，说明这条路不只是学术结论。

论文：arXiv 2510.22049 · PDF：本地阅读 现代推荐系统越来越依赖用户历史序列来提升效果。从HSTU到SIM、TWIN，序列建模的进展反复证明：把用户更长的行为历史喂给模型，通常能换来更好的预测。但当序列长度从几百扩展到上万甚至十万级时，工业系统立刻撞上三堵墙——训练要处理每天百亿级样本，推理有严格的延迟上限，GPU成本随序列长度线性甚至超线性膨胀。 VISTA（VIrtual Sequential Target Attention）试图从架构层面拆掉这堵墙。它的核心主张很直接：把“从候选物品到用户历史”的传统目标注意力分解成两个阶段——先把超长历史压缩成几百个摘要嵌入，再让候选物品去注意这些摘要。摘要嵌入离线算好、缓存起来，下游模型训练和推理只做第二阶段，计算成本与原始历史长度脱钩。 这篇论文的真实地位需要说清楚：它不是纯学术基准上的刷榜工作，而是一个工业系统论文。作者来自Meta与耶鲁大学，方法在Meta生产视频推荐系统上完成了在线A/B测试，报告了0.5%的核心消费任务提升和94%的推理GPU资源节省。公开数据集上的实验更多是验证注意力机制本...
