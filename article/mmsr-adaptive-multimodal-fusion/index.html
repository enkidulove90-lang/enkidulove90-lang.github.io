融合顺序不该是超参：MMSR 用模态增强图做自适应多模态融合

发表于2023-08-30|更新于2026-11-02|推荐系统多模态推荐
|总字数:1.2k|阅读时长:3分钟|浏览量:

论文：arXiv 2308.15980 · 代码：GitHub

多模态序列推荐里有个长期争论：模态特征应该在早期（拼进 item 表示再送序列模型）还是晚期（序列模型各跑一遍再融合）融合？MMSR 的立场是——这个问题不该有全局答案，不同用户、甚至同一用户的不同行为，最优顺序都不同，所以要让模型自己决定。

现象：融合顺序和序列长度纠缠在一起

这张案例分析把”模态序列”的两种组织方式摆在一起对比：Order/Match 指按原始时序排列的模态序列，disordered 指打乱顺序后的序列。论文用这张图说明一件事——模态之间的时序依赖本身携带信息，如果把模态序列当成无序的集合去融合（晚期融合的典型做法），这部分信息就丢了；反之如果强行按固定顺序早期融合，又会把”某个模态主导”的假设硬编码进模型。

机制：把用户历史建成”模态增强图”，让节点异步更新

MMSR 的做法是把每个用户的历史序列展开成一张图：

  • 同质节点之间的边表示模态内的序列关系（图像→图像、文本→文本），保留时序；

  • 异质节点之间的边表示跨模态依赖（同一物品的图与文）。

图传播时引入双注意力——对同质邻居和异质邻居用两套注意力，避免”邻居类型混在一起平均”这种常见退化。最关键的是update gate：每个节点的表示可以异步更新，也就是不同节点可以处在不同的”融合阶段”。这等价于让模型为每个节点自适应地挑选融合顺序，而不是全图统一 early 或 late。

框架图左侧是整体流程（用户历史 → 模态增强图 → 传播 → 兴趣表示），右侧拆开聚合模块：可以看到同质/异质两类边分别走不同的聚合路径，再被 update gate 控制更新节奏。图上用不同颜色区分节点类型，视觉上就能看出”一张图里同时存在两种关系”，这是它区别于普通 GNN 序列推荐的地方。

实验

六个数据集（Beauty / Clothing / Sports / Toys / Kitchen / Phone，均为图+文两模态）：

主结果：相对最强基线平均 **HR@5 +8.6% / HR@20 +2.8%、MRR@5 +17.2% / MRR@20 +7.6%**。基线覆盖三类：序列模型（GRU4Rec、SASRec、SR-GNN、STOSA 等）、多模态序列模型（NOVA、DIF-SR、SASRec^F、GRU4Rec^F 等）、以及图类多模态方法（MMGCN、MGAT、BM3）。

一个细节值得记：用”给序列模型加模态特征”的朴素做法（表中带 F 上标的 SASRec^F、GRU4Rec^F）在 Beauty 上甚至不如不加（SASRec^F HR@5 6.4021 vs SASRec 6.1900 略高，但 GRU4Rec^F 3.7682 明显低于 GRU4Rec 5.6420）——这说明”要不要加模态”和”怎么加”是两件事。

消融：论文拆开同质关系与异质关系后发现最优选择随数据集变化——Sports 上同质关系（模态内序列）贡献更大，而 Beauty、Clothing 上异质关系（跨模态依赖）更有利。这恰好实证了”融合顺序应自适应”的动机。

这张图对比 MMSR 与两个最强基线（SASRecF、DIF-SR）在”图像/文本特征按比例缺失”时的表现。横轴是缺失比例、纵轴是性能。读法是看曲线斜率：MMSR 的下降更平缓，说明显式建模”模态间依赖”的图结构在模态缺失时比”把特征塞进序列”更抗损——这也符合直觉：图里保留的关系不会因为某个模态缺失就整段消失。

总结

MMSR 的贡献是把”融合顺序”从超参变成了可学的东西：用异质图显式表达模态内序列关系与跨模态依赖，用双注意力区分两类邻居，用 update gate 让节点异步更新。消融给出的结论也很清楚——没有全局最优的融合顺序，只有按数据集/按节点自适应。顺带一个可迁移的观察：朴素地把多模态特征喂给序列模型，收益可能为负。
