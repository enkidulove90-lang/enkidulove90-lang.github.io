> 论文：[arXiv 2508.04247](https://arxiv.org/abs/2508.04247)

模态缺失（missing modality）在不完整多模态推荐里是个被反复处理的问题，但 I³-MRec 指出一个评测层面的细节常被忽略：**"训练时有缺失"和"测试时有缺失"是两件不同的事**，两者对模型的要求并不一样。

## 两种设定，两种难度

论文把评测分成两类：

- **FTMT**（Full Training, Missing Test）：训练时模态齐全，测试时才有缺失；
- **MTMT**（Missing Training, Missing Test）：训练和测试都缺。

![Baby 数据集上两种设定下的性能](/images/i3mrec-two-settings.jpg)

*这张图在 Amazon Baby 上把两种设定并列画出来（"Full Modality"对应无缺失的上界，另外两组对应 FTMT / MTMT）。读法是看**同一方法在两根柱子之间的落差**：落差越大，说明模型对"缺失出现在训练还是测试"越敏感。论文用这张图支撑一个判断——只在测试时缺失的问题，和训练时就缺失的问题，不能用同一套方法论对付；鲁棒表示学习类方法（MILK、SiBraR 那一类）在两种设定下的表现差异尤其明显。*

![不同缺失模态类型下的性能](/images/i3mrec-missing-types.jpg)

*第二张图把"缺什么"也拆开了：缺失视觉、缺失文本、还是两者都可能缺。结论是**缺失类型对性能的影响并不对称**——这与多模态推荐里"文本贡献更大"的普遍观察一致，也意味着一个模型如果只在"随机缺失"下评测过，未必能应付"系统性缺某一模态"的真实场景。*

## 机制：要的是"跨缺失模式不变"的表示

论文的思路来自一个明确的假设：**真正有用的用户/物品偏好表示应当对"哪些模态可用"不敏感**。实现上它把两件工具合起来：

- **信息瓶颈（IB）**：约束表示只保留与推荐目标相关的信息，压掉与模态可用性相关的"伪相关"。缺哪个模态就改变表示，说明表示里混进了模态存在性这种与偏好无关的信息。
- **不变风险最小化（IRM）**：把不同的"模态可用性模式"当作不同的环境（environment），要求表示在各环境下都取到最优——这是"不变性"的标准做法。

![I³-MRec 整体框架](/images/i3mrec-framework.jpg)

*框架图给出完整流程：先用基于图的协同过滤范式学出面向偏好的用户/物品表示，再在多个"模态可用性模式"上施加不变性约束，最后融合出对缺失鲁棒的表示。注意它没有"补全"模块——这和不完整多模态推荐里的另一条主线（把缺失模态补出来）是两种哲学：**补全派要求"恢复内容"，不变派要求"忽略缺失"**。*

## 实验

三个 Amazon 数据集（Baby、Sports、Clothing），两种设定下各报 R@20 / N@20：

| 方法 | FTMT（Baby / Sports / Clothing） | MTMT（Baby / Sports / Clothing） |
|---|---|---|
| LATTICE | 0.0632 / 0.0511 / 0.0743 | 0.0542 / 0.0437 / 0.0627 |
| SMORE | 0.0792 / 0.0610 / 0.0903 | 0.0712 / 0.0540 / 0.0756 |
| MILK | 0.0415 / — / — | 0.0375 / — / — |
| SiBraR | 0.0472 / — / — | 0.0429 / — / — |

两个值得注意的现象：

1. **SMORE 是最强基线**（MTMT 设定下 Baby 仍有 0.0712），而不是那些专门为"缺失模态"设计的方法；
2. **专为缺失设计的 MILK 与 SiBraR 反而明显落后**（Baby FTMT 0.0415 / 0.0472）。论文的解释是：这两者主要面向冷启动场景，没有充分利用协同过滤信号——"为缺失而生"不等于"更适合缺失"。

**消融**（Baby，逐块加入）：

| 变体 | FTMT（R@20 / N@20） | MTMT（R@20 / N@20） |
|---|---|---|
| 仅 IB | 0.0763 / 0.0338 | 0.0596 / 0.0254 |
| IB + IRM | 0.0799 / 0.0348 | 0.0638 / 0.0279 |
| 再加第三个组件 | 0.0809 / 0.0351 | 0.0727 / 0.0307 |
| 完整 I³-MRec | **0.0817 / 0.0361** | **0.0744 / 0.0325** |

这张表最有信息量的不是最后一行，而是**两个设定下的提升节奏不同**：IB 单独就能把 FTMT 从 SMORE 的水平推到 0.0763，但 MTMT 只有 0.0596；随着组件逐个加入，**MTMT 的提升幅度（0.0596 → 0.0744，约 +25%）远大于 FTMT（0.0763 → 0.0817，约 +7%）**。换句话说，"不变性"这套设计主要是在"训练时就缺"的场景里起作用——这正好呼应论文开头对两种设定的区分。

**缺失率扫描**：在 Baby 上把缺失比例逐步提高，I³-MRec 相比 LATTICE、SMORE、MoDiCF 的 Recall@20 全程领先，且在归一化后（以无缺失设定为基准）的曲线下降更平缓。

## 总结

I³-MRec 有两个可带走的东西。第一是**评测视角**：FTMT 与 MTMT 必须分开看，一个方法在"测试才缺"下表现好不代表能应付"训练就缺"。第二是**方法论选择**：与其去补全内容，不如让表示对"哪些模态可用"不敏感（IB + IRM 这套组合），并且论文的消融显示这套思路的收益主要落在更难的 MTMT 设定上。附带一个反直觉的结论——专为缺失设计的方法未必强于通用多模态推荐方法（SMORE）。
