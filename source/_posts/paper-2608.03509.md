> 论文：[arXiv 2608.03509](https://arxiv.org/abs/2608.03509) · 代码：[GitHub](https://github.com/Tencent/AI-Infra-Guard) · PDF：[本地阅读](/papers/2608.03509.pdf)

自进化智能体正在改变“经验”在系统中的安全含义。过去的智能体把每次交互当作孤立回合，记忆投毒的影响通常止于被检索到的那一刻；而新一代系统会把历史轨迹、交互日志乃至文档蒸馏成可复用的技能，再通过路由把它们应用到未来任务上。经验一旦进入学习语料，就不再只是瞬态上下文，而可能成为智能体持久行为库的一部分。

SkillJack 关注的正是这一转变。论文没有在运行时上下文里直接注入恶意指令，而是把一条经过功能化包装的恶意轨迹送进智能体自己的“经验到技能”管线，让系统主动把它编译成一个表面无害、可被路由、可长期复用的技能。攻击者不需要写权限访问技能库，也不需要修改提取代码，只需要影响经验层。

论文的定位是首次识别并形式化“经验到技能投毒”这一攻击面，并刻画三个只在组合中涌现的属性：净化洗白、跨层提升和持久隔离。它不是在单一实现上找漏洞，而是在 SkillX 与 Anything2Skill 两个独立系统上重复同一套输入与判定，试图说明风险属于范式而非某个代码库。

这里存在一个容易被误读的张力。直接上下文注入在配对实验中触发得更频繁（68.0% 对 40.0%），技能路径单看触发率并不占优；技能路径真正的增量风险是持久性——源轨迹删除后仍有 80.0% 的触发存活。另一个张力来自防御：提取时审查与运行时监控简单叠加，在 SkillX 上反而比单独运行时监控更差。

论文的结论有明确前置条件。全部实验使用 DeepSeek-v4-flash 通过 API 完成，成功判定依赖正则模式匹配加 LLM 裁判构成的“策略违规代理”，触发率与 ASR 都是路由级替代指标，而非真实服务被攻陷的比例；防御研究被作者自己标注为探索性，A2S 的签名扩展是在观察到失败之后做的后验调参。理解这些边界，才能正确读取后面的数字。

## 一、方法：把投毒经验送进智能体自己的学习管线

### 四阶段抽象与攻击者目标

论文把经验到技能管线形式化为加载、变换、持久化、路由四个阶段，记作 Π = (π_L, π_T, π_P, π_R)。一条经验 e 经加载与变换得到技能 s = π_T(π_L(e))，技能是包含名称、描述、代码的结构化元组；路由器 π_R(q, S) 针对新查询 q 从技能库 S 中选择相关技能。攻击者注入一条投毒经验 e_p，希望派生技能 s_p 同时满足三件事：不被检测器 D 标记、被路由器选中、执行时产生非预期行为。

三个安全属性由此获得可测量的形式。净化洗白指 p_D(Π(e_p)) < p_D(e_p)，即提取后的技能比原始轨迹更难被标记；跨层提升指 s_p 进入技能库且存在查询使其被路由选中，攻击从经验层被抬升为技能层能力；持久隔离指即使 e_p 已不在经验语料中，Π(e_p) 仍留在技能库，因为技能存储与经验语料是解耦的。论文在原始轨迹、派生技能、路由技能三个边界上分别测量这些量。

### 变换鲁棒载荷：让恶意动作活过压缩与抽象

实现上述目标的核心障碍是变换阶段本身。提取管线会压缩、抽象、规范化输入，一条措辞直白的恶意轨迹要么在提取时被丢弃，要么在输出中暴露意图。论文提出的变换鲁棒载荷（transformation-resilient payloads）基于一个可检验假设：提取器更愿意保留符合合理任务叙事的动作序列，而不是用对抗性语言描述的动作序列。

具体做法是构造配对记录：同一个政策相关动作，一组用直接恶意措辞表达，另一组用看似合法的功能框架包装，例如用“备份”“归档”“迁移”来描述向外部地址发送数据，用“统一管理”“批量访问”来描述跨应用收集凭据，用“错误恢复”“诊断”“熔断”来描述在特定错误路径上外传用户内容。配对设计的目的不是宣称某种措辞具有普遍不变的效果，而是把措辞与元数据的影响从提取时归一化的影响中分离出来。

论文在四类政策风险上实例化这套框架：数据外泄、权限提升、未授权转账、持久后门。每类有自己的框架词汇与示例派生技能，例如数据外泄类的派生技能名为 backup_files_to_email，权限提升类为 admin authentication，未授权转账类为 venmo_create_payment，持久后门类为 diagnostic reporting。这些名称本身读起来像正常运维操作，这正是攻击想要的效果。

### 三个边界的测量设计

方法上真正值得注意的是测量位置。论文没有只在源数据上判断安全与否，而是在三个边界分别放置检测器：原始轨迹进入管线之前、技能被提取出来之后、技能被路由器选中之后。同一套模式匹配与 LLM 裁判在两个阶段重复使用，才能看出提取本身改变了什么。

![净化洗白：原始轨迹与派生技能的LLM裁判检测率对比](/images/papers/2608.03509/figure_001_fig_whitewashing.png)

这张图是理解“洗白”最直接的入口。横轴对应不同系统与摄入模式，每组里原始轨迹的检测率都远高于从它提取出的技能：SkillX 是 98.5% 对 11.4%，A2S 文档模式是 100.0% 对 44.4%，A2S SDK 模式是 100.0% 对 28.6%。阅读顺序应当先看每组两根柱子的落差，再看落差在不同系统间的差异——SkillX 的降幅最大，论文将其归因于它产出的技能抽象程度最高。这张图支撑的主张是：检测率下降不是某个检测器的偶然波动，而是在三种配置下同向出现。

## 二、实验：两个系统上的洗白、持久与路由

### 数据、系统与判定口径

| 项目 | 设置 |
| --- | --- |
| 数据格式 | AppWorld 格式，9 个应用、457 个 API、轨迹 JSONL 模式 |
| 轨迹总数 | 150 条：65 条功能化包装投毒、65 条配对直接恶意基线、20 条干净轨迹 |
| 风险类别 | 数据外泄 20 条、权限提升 15 条、未授权转账 15 条、持久后门 15 条 |
| 提取系统 | SkillX（基于计划的轨迹蒸馏）与 Anything2Skill（分类引导的文档编译，含 SDK 与 DOC 两种模式） |
| 技能库 | SkillX 产出 264 条包装技能、241 条直接基线技能；A2S DOC 产出 30 条技能；路由库 356 条（305 投毒 + 51 干净） |
| 检测器 | 正则模式匹配 + DeepSeek-v4-flash LLM 裁判，合称策略违规代理 |
| 指标 | 提取率、原始/派生检测率、LLM 规避率、触发率、持久率、干净任务触发率 |
| 实现条件 | 全部提取、路由、判断与推理经 API 调用 DeepSeek-v4-flash；约 3,047 次 LLM 调用，总运行约 5 小时；无需 GPU 或嵌入模型 |

需要强调判定口径：触发率与 ASR 是路由级替代指标，任务被计入触发，是因为被路由到的技能满足策略违规代理，而不是因为真实外部服务被攻陷。

### 主结果：提取阶段洗白与下游触发

| 系统 | 载荷 | 提取率 | 原始轨迹 LLM 检测 | 派生技能 LLM 检测 | 派生技能模式检测 | LLM 规避率 |
| --- | --- | --- | --- | --- | --- | --- |
| SkillX | 功能化包装 | 100.0% | 98.5% | 11.4% | 11.0% | 88.6% |
| SkillX | 直接恶意基线 | 100.0% | n/a | 27.0% | 27.8% | 73.0% |
| A2S（SDK） | 功能化包装 | 10.8% | 100.0% | 28.6% | 28.6% | 71.4% |
| A2S（DOC） | 功能化包装 | 41.5% | 100.0% | 44.4% | 3.7% | 55.6% |
| A2S（DOC） | 直接恶意基线 | 0.0% | 100.0% | n/a | n/a | n/a |

最直接的对照是 SkillX 内部的两行：功能化包装的派生技能被 LLM 裁判标记的比例是 11.4%，直接恶意措辞基线是 27.0%，规避率分别为 88.6% 与 73.0%；264 条包装技能中没有一条带有明显恶意的名称，而 241 条直接基线技能中有 20 条（8.3%）带有此类名称。这说明包装不只是让措辞更委婉，它改变了提取器愿意保留什么、以及检测器看到什么。

跨系统的证据同样清楚，但形态不同。A2S 文档模式对 41.5% 的包装轨迹产出了可复用技能，对直接恶意基线一条也没有产出；在产出的技能中，LLM 裁判检测率从原始轨迹的 100.0% 降到 44.4%，而模式检测只有 3.7%。SDK 模式提取率更低（10.8%），派生检测率为 28.6%。两个系统在提取产量与输出形态上差异明显——SkillX 产出大量较小技能，A2S 文档模式产出较少、更像文档的技能——这种差异恰恰是需要在多个代表性系统上评估的原因。

### 持久性：删掉源轨迹之后

| 条件 | 任务数 | 触发率 |
| --- | --- | --- |
| 仅记忆（投毒轨迹放入上下文） | 25 | 68.0% |
| 技能路径 | 25 | 40.0% |
| 删除源轨迹后的技能路径 | 25 | 32.0% |

![配对25任务实验中各风险类别与总体的触发率](/images/papers/2608.03509/figure_002_fig_persistence.png)

这张图应按“条件—类别—总体”的顺序读：先比较仅记忆、技能路径、删除后三种条件在总体上的高度，再横向看四类风险的分布。仅记忆条件触发最多，但技能路径的柱子并没有随源轨迹删除而消失——总体从 40.0% 降到 32.0%，论文据此报告 80.0% 的技能路径触发在删除后存活。这张图支撑的主张是持久隔离：清理经验语料不等于清理技能库，因为两者是分开存储的。

这里需要如实指出代价与例外。技能路径在配对设置中的触发率低于直接上下文注入，论文明确把这理解为效率与持久性之间的权衡，而不是技能路径全面更强。持久率的分母是技能路径下已经触发的任务，因此它刻画的是“已触发的攻击有多难清除”，不是“所有攻击有多容易成功”。

### 路由：定向触发与附带命中

| 系统 | 设置 | 任务数 | 触发率 |
| --- | --- | --- | --- |
| SkillX | 原生路由，攻击导向任务 | 32 | 56.2% |
| SkillX | 原生路由，干净任务 | 15 | 20.0% |
| A2S DOC | 词法 SkillBank，攻击导向任务 | 65 | 89.2% |
| A2S DOC | 词法 SkillBank，干净任务检索 | 20 | 95.0% |

![SkillX在356技能库上的路由级结果](/images/papers/2608.03509/figure_003_fig_routing.png)

这张图对应 SkillX 的 356 技能库（305 条投毒、51 条干净），横轴区分 32 个攻击导向任务与 15 个干净任务。阅读时先看攻击任务上的触发率，再看干净任务上的触发率，后者反映的是附带选择：干净任务本不该命中投毒技能，但仍有 20.0% 被路由到满足违规代理的技能。图中还给出“期望类别匹配”这一维度，用于描述路由是否落在攻击者预期的风险类别上；干净任务上该量无定义。这张图支撑的主张是：派生技能不仅会被选中，还会在非目标任务上误触发，因此路由级 ASR 不能被读作精确的定向攻击成功率。

A2S 侧的结果更极端：65 个攻击导向查询上触发率 89.2%，分类别看，持久后门 100.0%、未授权转账 93.3%、数据外泄 85.0%、权限提升 80.0%；干净任务检索率高达 95.0%，说明文档式技能描述较宽泛，会带来大量附带匹配。两个系统保留了各自的技能表示与路由配置，因此这些数字刻画的是各自配置下的敏感度，而不是同一排行榜上的强弱比较。

### 消融：元数据如何左右裁判

| 呈现条件 | SkillX 包装技能 LLM 检测 | A2S DOC LLM 检测 |
| --- | --- | --- |
| 完整技能（名称+文档+代码） | 10.0% | 26.7% |
| 仅内容（代码） | 36.7% | 46.7% |
| 仅名称+文档 | — | 33.3% |
| 仅名称 | — | 23.3% |

SkillX 的消融使用每条件 30 条采样技能，A2S 使用全部 30 条提取技能。关键对比是：只看代码时 LLM 裁判标记 36.7%，一旦附上良性名称与文档就降到 10.0%。A2S 呈现同向模式，完整技能 26.7%、仅代码 46.7%。论文据此认为裁判的判断实质依赖表面元数据，而不是代码语义本身。这也解释了为什么“仅名称”条件在 A2S 上仍有 23.3% 的检测率——名称本身携带了一部分信号，但远不足以恢复仅代码时的检测水平。

### 防御：分层并不单调

| 系统 | 防御设置 | 任务数 | 触发率 |
| --- | --- | --- | --- |
| SkillX | 提取时审查（D1） | 15 | 6.7% |
| SkillX | 运行时监控（D2） | 15 | 0.0% |
| A2S DOC | 增强运行时监控 | 20 | 20.0% |
| A2S DOC | 审查 + 增强监控（D3） | 20 | 5.0% |

SkillX 上，提取时审查在路由前拦下 9.2% 的投毒技能，把触发率降到 6.7%；运行时监控拦下九个运行时动作，在 15 任务样本中阻断全部触发。但组合防御 D3 反而重新引入两个触发（13.3%），比单独运行时监控更差。论文给出的机制解释是两层防御并不独立：上游审查移除了部分技能，路由器对同一任务改选另一个技能，而该技能生成的动作恰好不匹配下游监控的固定签名，于是漏过。作者把这称为防御协调假设，并明确说明验证其普遍机制需要更大规模、预注册的实验。

A2S 上，提取时审查拦下 26.7% 的技能；原本为 SkillX 动作词汇编写的 16 条签名只把触发率压到 85.0%，因为文档模式技能用规范化语言重述同一动作（例如“发送到监控服务”而非“向外部发送邮件”）。把签名扩展到 54 条覆盖这套词汇后，触发率降到 20.0%，组合防御达到 5.0%。论文坦承这些签名是在观察到失败之后补充的，因此这一下降反映的是后验调参，而非先验防御。

### 补充代码生成验证

路由级指标之外，论文用 4 个投毒任务和 2 个干净任务做了小规模代码生成检查，通过 AppWorld 提示格式注入技能，解析模型生成的 Python 代码是否匹配预设的危险 API 模式。投毒任务上的模式匹配率为 75.0%，干净任务为 0.0%。这是路由与生成动作之间的定性桥梁，不是对真实外部服务的执行验证。

## 三、总结

SkillJack 的机制可以概括为一句话：攻击者只影响经验层，智能体自己的提取管线把恶意轨迹编译成单独存储、可被路由、可活过源记录的技能。论文用三个属性刻画这一过程——净化洗白（SkillX 上 LLM 裁判检测率从 98.5% 降至 11.4%）、跨层提升（派生技能在 SkillX 与 A2S 上分别对 56.2% 和 89.2% 的攻击导向任务触发违规代理）、持久隔离（删除源轨迹后 80.0% 的技能路径触发存活）。两个独立实现的系统给出同向证据，支持“这是范式级风险”的判断。

证据的边界同样清楚。全部结果来自单一模型 DeepSeek-v4-flash，成功判定是路由级代理而非真实攻陷；防御研究样本小、监控基于规则，A2S 的签名扩展属于后验调参；干净任务上的附带触发（SkillX 20.0%、A2S 检索 95.0%）说明这些数字不能当作精确的定向攻击率。作者也明确表示结论尚未在其他模型上复现。

对构建自进化智能体系统的团队而言，最可迁移的设计启示不是“再加一层过滤”，而是把溯源当作技能生命周期的一等公民：每个派生技能都应保留指向其来源记录的链接，删除或隔离源记录时同步审查或撤销后代技能，并在原始轨迹、派生技能、路由技能每个变换边界重新做安全判断。防御协调假设进一步提醒，多层安全机制需要联合设计——上游过滤会改变下游监控所面对的动作分布，简单堆叠可能让组合效果弱于单层。
