配置 Clash 遇到的问题和总结

一、前言

Clash 是一款功能强大的代理工具，支持多种代理协议和规则分流。它常用于科学上网、网络调试等场景。本文总结了在配置 Clash 过程中遇到的常见问题以及解决方法，帮助大家快速解决遇到的坑。

二、常见名词解释

1. 系统代理 / Tun 模式

系统代理：

  • 系统代理会在系统的特定位置（如注册表、系统变量等）设置代理程序的监听端口信息。
  • 网络请求的应用会读取这些配置，将流量发送至代理程序。
  • 不同操作系统的代理配置方式不同。
  • 但是，并非所有程序都遵循系统代理的“约定”，最终决定是否使用代理取决于开发者的意愿。

特点：

  • 自发性：程序根据系统配置选择代理。
  • 不支持 UDP 流量代理（如游戏数据包）。

Tun 模式：

  • Clash 创建虚拟网卡，通过重定向网络请求的方式拦截所有流量。
  • 它不依赖应用程序是否遵循系统代理配置。

特点：

  • 支持 TCP 和 UDP 流量代理。
  • 无需额外配置应用程序。

2. 规则 / 全局 / 直连模式

规则模式： 根据配置文件中的规则进行流量分流，决定流量是通过代理节点还是直连。

全局模式： 所有流量都通过手动选择的代理节点。

直连模式： 所有流量都直接通过本地网络，不经过代理。

3. 服务模式

  • Clash 提供服务模式，以管理员权限运行代理程序。这样即使你以非管理员身份启动 Clash，也可以正常运行 TUN 模式。
  • 使用服务模式时，代理内核程序由服务进程管理，不会因关闭界面应用程序而退出。
  • 需要注意的是，不同内核的 TUN 模式需要对系统防火墙放行特定的内核程序（如 verge-mihomo 和 verge-mihomo-alpha）。

4. UA（User Agent）

  • UA 是 HTTP 请求头中的字段，用于标识客户端的类型。
  • 订阅服务商通常会通过 UA 判断你使用的代理工具，并提供相应的配置文件。

5. Meta 内核

  • Clash Meta（Mihomo 内核）是基于 Clash 的一个开源分支。
  • 与闭源的 Clash Premium 不同，Meta 提供了更多的自由度和功能。

6. Alpha 内核

  • Alpha 内核是 Clash Meta 的测试版本。
  • 更新频率较高，通常包含最新的 bug 修复和实验性功能。
